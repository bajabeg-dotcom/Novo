# K03-P user-selected Factory replacement proposal audit — 2026-08-14

## Decision

**PASS** for the bounded Suggest-only proposal scope.

The K03 Change backend, MIDI writer, rollback and Verifier remain NO-GO. This
module does not modify a MIDI event even after user approval.

## Preconditions

A proposal requires:

- an actual immutable M10 segment;
- the corresponding K02 identity object;
- complete `CC00.CC32.PC` source address;
- K02 status `FACTORY_CONFIRMED` or `USER_SLOT_CONFIRMED`;
- exact user-selected K01 Factory target;
- compatible source/target item kind;
- actual source events matching M10 selection references;
- P01/P02 validation.

`user_selected=false` is always blocked.

## Exact-event safety

The first K03-P scope never inserts Bank Select or Program Change events.

- Program Change must be an existing exact event at the M10 segment boundary.
- CC00/CC32 changes require existing events at the same boundary.
- A Bank Select event shared by another M10 segment is blocked.
- An inherited Bank Select event from another boundary is blocked.
- Unchanged address fields do not produce mutations.
- A no-op target is blocked.

This prevents a segment replacement proposal from silently changing an earlier
or later segment that inherited the same bank state.

## Status and kind policy

Blocked source states:

- `CONFLICT`
- `UNKNOWN`
- `INCOMPLETE_ADDRESS`
- `NO_PROGRAM`

A confirmed Factory Sound can target only another Factory Sound. A User Drum
Kit slot can target only a Factory Drum Kit and receives `HIGH` risk. A normal
Factory-to-Factory proposal receives `MEDIUM` risk.

## Proposal output

The output is one P01 Change Plan containing:

- K03 named/versioned rule;
- exact K01 target and manual pages;
- K02 segment identity evidence;
- explicit USER_SELECTION evidence;
- segment/channel/tick/note/address measurements;
- exact CC/PC event-field mutations;
- expected difference and protections.

Plan phase remains `SUGGEST` and `apply_authorized=false`.
